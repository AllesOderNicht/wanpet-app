# 把图片做成可用场景素材

这是仓库内的美术生产 SOP，不代表产品已经支持任意图片自动变成可玩的资产。当前阶段不调用视频生成：新增素材使用生图，已有动画可继续复用。用户明确改变阶段要求时按新要求处理，不把这个阶段约束扩展到其他项目。

从仓库根目录工作。先检查现有修改，再读 `apps/godot/data/morning-interior.json`、`morning-courtyard.json`、`morning-pet.json`，以及[画面问题与路线](../../docs/refactor-2026-10-29/03-technical-design.md)。移动端实际入口是 `rn_scene.gd`，不要拿独立旧客户端的截图证明移动端已修好。

## 先定位置，再生成图片

明确素材属于背景、地面、世界物件还是前沿遮挡。当前场景使用 390×844 逻辑坐标；它与 PNG 像素尺寸不同。宠物和家具共用一套地面坐标与比例，缩放画面时保持等比。

- 背景只画远处装饰和连续地面。准备让宠物走过、绕过或使用的家具单独生成，不烘焙进底图。
- 道具统一固定视角、光向和水彩画风，留透明边缘。记录落地点、尺寸和前后关系；深色底不能代替真正的透明通道。
- 宠物姿势使用同一角色参考，保持体形、花纹、脚底和身体比例。缩放按动作族校准，避免每帧伸缩；新静态姿势不能声称具有完整步态或骨骼动画。

生成或修改图片使用环境提供的内置 `image_gen` 工具，并按可用 imagegen skill 的要求调用。编辑已有图时先查看，再传入明确的参考路径。不要调用仓库中的视频生成脚本，也不要运行外部安装脚本来补工具。若工具不可用，继续做配置与验证，明确缺少哪张素材；不要把示意图当成最终资源。

## 接入同一个空间

`room.gd` 的世界节点已支持 Y 排序。穿插问题要分别检查遮挡、通行和接触，不能只提高宠物的 z 值。

| 配置 | 实际含义 |
| --- | --- |
| `position` | 物件在场景中的地面位置 |
| `pivot`、`scale`、`region` | 图片中的锚点、固定倍率和裁剪区域 |
| `collision`、`walkable` | 不能走的占地与允许行走的地面 |
| `life_slots` | 使用物件时的站位、朝向、姿势与接触点 |
| `front_part` | 窝沿等需要挡在身体前面的独立画面部分 |

优先用 `life_slots` 的 `object_id` 加 `offset` 绑定家具。`offset` 和 `contact` 在这里是场景逻辑单位，不随道具图片的 `scale` 再缩放；采用独立 `position` 时，接触点也是场景坐标。不要另写一个容易漂移的食盆绝对坐标。

`front_part` 使用自己的纹理、锚点和 `depth_offset`，与主体放在同一排序体系。拆分部件时保证透明边缘和覆盖范围正确，不靠整张家具盖住宠物。移动家具走 `room.move_prop`，同步主体、前沿与使用位置；当前实现拒绝移动带碰撞的物件，扩展前必须同时更新导航与碰撞。

调整猫的可见大小后，复查脚底碰撞范围和身体伸出的余量。吃饭检查嘴与碗口，睡觉检查床沿和身体，如厕检查入口及退出路径，阅读检查视线与书的位置。不能只验证“目标点可达”。

## 保存来源并打包

最终 PNG 放入 `assets/godot/` 合适子目录，保留旧版本以便比较。给 `assets/godot/manifest.json` 添加路径、SHA-256、生成来源、作者/制作方式、提示词、参考图、透明属性和实际审核状态。模型版本不可见就如实记录；不要声称 AI 生成等于已完成所有权利核验。配置中的资源引用与清单路径必须一致。

`scripts/prepare-rn-game.mjs` 会收集配置和脚本引用的资产，并验证哈希。新增运行脚本、配置或测试时，检查它们是否在暂存清单里。先用 Node 24 运行：

```sh
node scripts/prepare-rn-game.mjs
```

在基础类型与单元检查通过后运行：

```sh
npm run mobile:prepare-game
```

这个构建使用固定 Godot 4.5.1 导入器，执行 RN 场景与生活测试，再生成 iOS PCK 和 Android 场景资源。可用 `MOBILE_GODOT_BIN` 指向匹配版本；不要混用旧独立客户端的 4.7.2 导入结果。遇到引擎错误保留日志并区分环境问题与脚本问题，不能把失败包装成通过。

## 看见实际画面再验收

在当前 RN 场景或同一 4.5.1 渲染环境中运行，保存并查看截图，至少覆盖进入、使用中、退出三种状态。检查窄屏与宽屏的裁切、手指可点区域、角色相对家具的大小、前后遮挡和动作切换。需要判断滑步或闪烁时连续观察；静态截图不能证明运动自然。

报告中区分生成成功、导入成功、脚本通过、可见场景检查与真机验收。聊天生成的一张图仍只是图片；成为可交互物件还需要上述配置、行为连接与检查。未实现的自动资产流水线或 3D 路线保留为待办。
