# 选定图一：保留原画的动态 UI 稿

更新：下文记录的形变方案已被用户否决并替换。当前使用24帧透明精灵图集，参见 SPRITE24.md；不再使用原图区域形变。

2026-10-18 用户选择第一张，并要求猫会动，完全还原图一的大小、风格和样子。

视觉基准：01-engawa.png（853×1844）。动态稿：01-engawa-motion-v1.mp4，Godot 实际渲染，390×844，180 帧 / 30 fps / 6 秒。不是生成视频。

保持原稿的全部文字、物件和构图。按比例适配画布，不重新排版、不拉伸。直接以原图猫所在的 atlas 区域渲染 Sprite2D，保留原始花纹与轮廓；着色器分别控制胸背呼吸、耳朵和尾尖微动。这里的 Sprite 是原画局部纹理，不是新的行走图集。

生成的透明猫重绘版本虽然相似，但轮廓有偏差，已放弃使用，保留 rejected-cat-cutout.png 供审查。home-clean.png 只用于宠物不在家时露出的底板；正常静止画面使用原画猫区域覆盖，因此没有重绘角色。

验证：静止帧相对同一 Godot 视口中的原图，RGB 平均绝对差约 0.00187 / 255；底部 UI 在运动帧间差异为 0。存在 GPU 采样造成的微小差异，不声称逐像素完全相等。猫区域运动帧差异约 5.00 / 255，需结合视频看动作，差异值本身不等于动画质量。

启动：.tools/godot/Godot.app/Contents/MacOS/Godot --path apps/godot --script res://tests/engawa_preview.gd -- --keep-open

范围：本次交付动态 UI 稿。猫保持原稿趴卧姿态，呼吸、耳尾微动和点击抚摸响应已实现；不会在这张稿里起身行走。原正式客户端主场景尚未替换，旧四方向行走动画问题也未宣称修复。行囊、收藏和庭院入口的信号已测试，预览本身没有连接对应完整页面或后端。此限制不应被误写为正式应用已完成。
