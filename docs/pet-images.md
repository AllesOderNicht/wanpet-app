# 图片聊天与旅行明信片

状态：2026-10-23 用户已确认按本方案开发，当前正在实现与验证；未发布或部署。下述验收清单全部完成前，不将代码存在或单项测试通过视为整体交付。

## 已确认的方向

- 上传图片同时支持看图聊天，以及按主人明确要求作为参考图生成或编辑图片。单纯上传不自动改图；宠物形象定制未纳入已确认范围。
- 图片生成允许直连火山方舟 Seedream，凭据后续配置；聊天继续使用现有 TokenHub Haiku。已验证并锁定 `doubao-seedream-5-0-flash-260915`，2K 单图报价 0.12 元，不静默更换模型。
- 聊天支持三种入口：用户明确要求生成或编辑图片；宠物提出生图提议，主人确认后执行；宠物偶尔主动赠图。普通聊天仍以文字为主。
- 主动赠图：只有聊到适合画出来的内容时，才有 5% 概率触发，每只宠物每天最多 1 张。用户明确要求的生图和旅行明信片另算。自动赠图失败当天不补发。
- 本地开发阶段所有账号、所有生图入口合计预算为 10 元/天。达到上限后文字聊天继续可用，旅行明信片复用或使用原画，明确生图请求显示额度已用完。
- 旅行明信片始终保持 10% 概率生成新图，其余从按目的地与主题共享的系统明信片图库复用。没有匹配图片时使用现有原创插画，不强制补生成，也不重新抽签。主人上传图片与私人聊天生图不进入共享图库。
- 出发时只抽签一次，旅行期间后台生成明信片。归来时领取奖励不等待图片，未完成先展示“明信片绘制中”；成功后补图，失败则使用匹配旧图或现有原创插画。图片状态不会改变已固化的经济奖励。
- 明信片呈现自己的游戏宠物，共享图片按目的地、主题与宠物外观匹配，不将不同外观的猫混用。用户上传的真实猫照片不会自动成为明信片参考图。
- 图片内容完全不进入 mem0：图片本身、识图描述、图片推断事实与生成图片均不作为长期记忆来源，也不将生成图当作真实经历。独立文字陈述继续沿用现有文字聊天的记忆规则。
- 主动赠图和明信片生图失败后不自动重新提交生成。明确请求的图片提供手动重试，每次重新检查预算。重试下载已经生成的图片不算重新生图。

## 聊天体验

输入区可选择图片，发送前可以预览、移除、补充文字。上传图片默认用于看图聊天；只有主人明确要求，才使用私人上传图生成或修改图片。没有明确选择的私人照片不会因 5% 主动赠图抽签而被使用。

主人直接要求生图时不再重复询问；宠物主动提出建议时显示确认入口，确认绑定具体创作内容。同一提议重复点击只启动同一任务。普通聊天不需要进入生图流程。

图片任务异步运行，显示排队、生成中、成功、失败或结果未确认。文字回复和现有宠物动作结果独立展示，不能在图片未保存成功时声称已经生成。明确请求的任务可以取消等待；供应商已接收的生成不承诺能够撤销或免除费用，取消后不自动把迟到结果插回聊天。

主动赠图只在符合创作场景的对话轮次抽签一次；同一轮重试不重新抽签。每天的赠图机会在任务提交前占用，失败也不再补发。符合条件的轮次 5% 触发，并不承诺每 20 轮一定出现一张。

## 明信片与共享图库

出发事务固定生图分支、宠物外观和风格版本，并建立持久任务。随机抽签由服务器完成，与 `tripId` 绑定；重复出发、领取、断网重试或重启不重新抽签。10% 是每次旅行的概率，不保证每 10 次旅行恰好生成一张。

10% 分支在旅行期间生成一张新画面；90% 分支从匹配图库选图。选定画面后保存引用，后续图库扩充不会改变已经领取的明信片。没有匹配图、额度不足、凭据未配置或生成失败时采用现有原创插画或匹配旧图，不能使用另一种外观的猫凑数。

成功生成并保存的系统画面可进入共享图库。图库仅使用应用拥有的宠物参考资源、已确定的目的地和旅行事实；不使用私人聊天、主人名字、主人记忆或上传照片。旅行尚未发生的事件不能写成真实经历。文字说明由应用单独排版，画面默认沿用原创水彩方向。

明信片收藏归领取它的玩家，画面资源可以共享；一张画面被多次使用不代表共享玩家存档。领取事务只结算原有奖励，图片成功或失败均不增发道具。生成晚于领取时，客户端通过独立图片状态查询补图，不改写原领取回执或用旧快照覆盖当前状态。

## 预算与任务恢复

全部生图入口使用同一本持久预算账本。提交前按锁定模型、分辨率和单张报价预留费用，确认结果后结算；并发预留不能越过 10 元日预算。第一版每次生成一张，关闭自动组图。无法核实报价时不开放付费生成，配置金额不是已经核实的供应商账单。

请求尚未发出时可以安全恢复待执行任务；一旦进入已提交或结果未确认状态，进程重启、超时及断网都不能自动重发生成请求。确认没有计费的失败才能释放预留；无法确认的费用继续保守占用预算。供应商支持结果查询时优先查询已有请求，否则保持结果未确认。用户手动重试是新的生成尝试，单独计额；同键网络重放不重复尝试。

自动任务失败按已确认策略回退。明确请求超时且结果未确认时，界面说明再次生成可能再次计费。图片下载、存储和缩略图处理可以针对同一结果重试，不调用新的生图请求。

## 图片、上下文与删除

沿用现有聊天保留规则：上传图和聊天生图随所属消息保留到主人删除。聊天图片默认私有，读取及用作参考图均验证账号归属；共享图库采用独立资源类别，不能通过修改客户端参数把私人图片放入其中。

图片与识图描述只用于可见、未删除消息的近期上下文，不进入 mem0 提炼队列。生成图不作为真实经历。任何存储的识图摘要都属于相应消息附件，并保留来源，不能混入普通文字记忆任务。

删除消息时同时撤销其图片访问、清理附件与识图摘要、递增上下文版本，并取消使用已删除来源的未完成任务。旧任务不能重新发布图片、恢复已删除消息或写入记忆。其他消息中已经独立保存的图片仍随其所属消息保留；删除原图不会追溯删除玩家已经保存到设备上的副本。已有文字长期记忆仍按原有管理规则单独删除。

本地开发使用持久私有文件目录保存附件和生成结果，数据库保存归属、来源、状态及引用；临时文件定期清理。备份需覆盖数据库与图片目录，不能只保存供应商临时图片链接。

## 建议采用的实现默认值

以下默认值随整体方案确认，实际兼容性仍须验收：

- 第一版每条消息最多 4 张图片，每张原文件不超过 10 MiB；系统相册和拍照后使用同一上传流程。服务端校验真实格式、像素和解码结果，去除 EXIF，生成聊天预览。客户端不能指定服务端本地路径或任意抓取 URL。
- 使用单独附件上传接口，聊天消息只引用已完成且本人拥有的附件 ID。不要把图片 Base64 塞进现有普通聊天的 16 KiB JSON 请求。
- Haiku 仍通过已锁定的 Codex SDK 接收图片；SDK 的 `local_image` 输入、TokenHub Haiku 识图与显式注入的连续上下文已实测。不因兼容失败静默更换聊天模型。
- Seedream 锁定 5.0 Flash `doubao-seedream-5-0-flash-260915`，2K 单图文生图与参考图编辑均已真实验证。5.0 lite 在当前账号返回 404，未采用。未配置时明确返回 `IMAGE_GENERATION_NOT_CONFIGURED`，看图聊天与文字聊天独立可用；识图链路失败需明确显示，不假装看过图片。
- 只增加项目自有图片工具，继续关闭 Codex 通用终端、文件修改、联网等能力。工具只接受业务对象 ID、提示词和受限参数，服务端决定模型、权限、费用与输出归属。
- 生图使用独立持久任务与增量事件，兼容现有每秒轮询；不占住最长 120 秒的聊天生成。服务端校验提议确认、抽签资格和预算，不能只靠提示词限制自动生图。
- 为与现有聊天额度保持一致，第一版每日额度按服务端 UTC 日期计算，客户端显示实际重置时间；一天最多一次主动赠图机会。后续可配置时区，但不能在变更时重置已消耗额度。
- 本次范围保持本地开发与验证；未配置生图凭据时先完成模拟供应商和任务恢复测试，真实模型验收明确标为待配置，不发布或部署。

## 实施顺序与验收

1. 先验证现有 Codex SDK → TokenHub Haiku 的文字加图片输入与连续看图上下文，再验证 Seedream 文生图、参考图编辑及单张计费。兼容失败要明确报告。
2. 增加附件、图片任务、预算预留及图库引用的持久化；先更新公开协议，再实现服务端和移动端。跨账号读取、猜测附件 ID、重复上传和删除后旧任务回写均应被拒绝。
3. 接通相册/拍照、预览、看图聊天、主动请求、提议确认与主动赠图。验证拒绝照片权限仍能文字聊天；上传失败可恢复，同一消息重复发送不重复占用赠图或生图预算。
4. 接通旅行明信片。固定随机源测试 10% 与 90% 分支、空图库、外观不匹配、预算耗尽、未配置、失败及领取早于生图完成；奖励与收藏不能因图片状态重复结算。
5. 故障测试覆盖“提交前”“请求已发出但未收到结果”“结果已到但文件保存失败”“完成后回执丢失”和服务重启，证明不会自动重复计费调用；单独验证手动重试计额与同键重放。
6. 验证所有账号并发请求不能超出日预算；5% 抽签在轮次重试时固定，当天赠图失败不补发。图片及派生摘要不写入 mem0，删除附件后后续上下文与旧任务均不可恢复。
7. iOS/Android 设备验证选图、拍照权限、弱网、上传进度、取消、图片预览及明信片补图。模型真实调用、设备验证与纯模拟测试分开记录，不互相替代。

## 本地运行

先使用 Node 24 安装锁定依赖、生成 Prisma 客户端，并对本地开发库运行 `npm run db:deploy`。新增迁移为 `202610230004_pet_images`；它只新增图片字段、表和索引，不改写旅行奖励。若使用受限运行角色，再由数据库所有者应用 `ops/grant-runtime.sql`。

在未入库的 `.env` 中配置：

```dotenv
SEEDREAM_API_KEY=<有权限调用该模型的火山方舟密钥>
SEEDREAM_MODEL=doubao-seedream-5-0-flash-260915
SEEDREAM_UNIT_PRICE_FEN=12
IMAGE_DAILY_BUDGET_FEN=1000
PET_MEDIA_DIR=.data/pet-images
```

`SEEDREAM_BASE_URL` 默认 `https://ark.cn-beijing.volces.com/api/v3`。模型、尺寸与价格已配套验证；修改型号需要同步适配和验收，不接受任意 Seedream 型号（例如参考图另收费的 Pro）。报价变化时先提高单价预留并重新核实；账本只表示应用预算，不是供应商发票。没有密钥时，上传和看图仍可用，生图显示待配置；未配置时的旧旅行不会在以后配置密钥后补发付费请求。

移动端依赖新增 `react-native-image-picker@8.3.0`，iOS 重新安装 Pods 并构建原生应用；仅刷新 JS 无法安装相册模块。服务端使用 `sharp@0.35.5` 校验解码、去 EXIF 和生成缩略图。原生相册先转换兼容格式；不能解码的 HEIC 返回明确错误。

文件目录不能经 Web 静态服务公开。文件权限为 0600、目录为 0700；通过认证接口读取，不返回供应商签名 URL。完整备份同时包含 PostgreSQL 和 `PET_MEDIA_DIR`，恢复时保留原路径与归属记录。未绑定上传、孤儿文件和临时文件超过 24 小时清理；已删除消息的附件立即不可访问，维护任务再移除文件。当前为单实例本地实现，不能将单机私有目录直接用于多实例部署。

## 图片 API

全部路径加 `/v1`，复用 Bearer 认证；所有 POST 必须带 `Idempotency-Key`。

| 方法和路径 | 请求与结果 |
|---|---|
| POST `/me/media` | `{data:base64}` → 201 `{id,width,height,kind}`；认证后单独允许 14 MiB JSON，解码图片最多 10 MiB |
| GET `/me/media/:id/content?preview=1` | 私有归属校验后返回 JPEG；`preview=0` 为大图，`Cache-Control: no-store` |
| POST `/me/media/:id/delete` | `{}`；只移除尚未绑定消息的本人上传 |
| POST `/me/pet/chat` | 原字段之外允许 `imageIds`（最多 4 个）、`imageIntent`；仅有图片时可省略文字，不因上传自动发送或生成 |
| GET `/me/pet/images/budget` | `{enabled,limitFen,usedFen,resetsAt}`；UTC 日期日预算，金额单位为分 |
| POST `/me/pet/images/:id/confirm` | `{}`；确认固定提示词和参考图，重复确认不再提交 |
| POST `/me/pet/images/:id/retry` | `{}`；仅明确请求或已确认提议的失败/未知任务，新增一次预算预留 |
| POST `/me/pet/images/:id/cancel` | `{}`；停止等待，不能保证供应商撤销费用 |
| GET `/me/postcards?before=jobId` | 当前账号已领取旅程的图片状态和图，最多 30 条；不提前泄露未领取奖励 |

聊天历史和事件接口附加 `images`、`imageJob`；生成任务状态为 `proposed → queued → submitted → saving → completed`，并可能进入 `failed/unknown/cancelled/fallback`。`unknown` 不自动重生；`saving` 只重试同一临时结果的下载，最多 8 次。恢复时超过 130 秒的遗留 `submitted` 保守标记为结果未知并保留预算占用。

主动作图抽签固定在聊天轮次中；带上传图片的轮次不参加赠图。工具层禁止赠图携带私人参考图。提议卡展示创作内容与引用图片，确认之前不计费。图片文字描述和助手文字不送进 mem0；带图用户消息及显式提及图片的后续记忆请求均被排除，纯文字独立事实继续遵循文字记忆规则。
