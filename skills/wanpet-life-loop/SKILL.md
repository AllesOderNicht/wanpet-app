# 接通一个宠物活动

这是仓库内的开发 SOP，不是已经部署的运行时工作流。以当前源码为准；设计文档里的待办不能当成已有功能。用户的新要求优先于此处的阶段约定。

从仓库根目录工作。先读 `AGENTS.md`，检查当前分支和已有修改，再按需读[功能方案](../../docs/refactor-2026-10-29/02-functional-design.md)与[技术方案](../../docs/refactor-2026-10-29/03-technical-design.md)。保留原宠物 ID、存档和不相关修改。

## 先写清楚这件事怎样发生

用一段话说明：谁提出活动、需要什么物件、何时允许开始、何时消耗资源、完成后改变什么、途中受阻怎么办。区分“宠物愿意做”“走到了”“正在做”“已经做完”；聊天说愿意吃饭不能直接增加饱腹或写入完成记忆。

当前 v2 协议用 `moving` 和 `using` 表示途中与使用中。Godot 回报 `started`、`arrived`、`complete` 或 `blocked`；服务端决定是否接受。读旧存档与旧回执的兼容规则后再扩展，不能无声改变待重试请求。

## 顺着同一条链修改

| 位置 | 要接上的内容 |
| --- | --- |
| `packages/contracts/src/index.ts` | 活动、地点、状态和请求结构；先定义双方约定 |
| `apps/server/src/pet-activities.ts`、`cat-life.ts` | 可选活动、前置条件、需求变化、资源预留与释放、使用时长、迁移 |
| `apps/server/src/cat-life-service.ts`、`app.module.ts` | 身份认证、版本检查、事务、幂等结果；必要时接入画像与照护接口 |
| `apps/server/src/pet-agent.ts`、`jev.ts`、`chat-service.ts` | 聊天和自主活动共用真实状态；模型只从允许的活动中选择 |
| `apps/godot/scripts/cat_life.gd`、`room.gd` 与房间配置 | 找到物件、移动、朝向、接触、姿势和阶段回报 |
| `apps/mobile/src/session/Session.ts`、`wire.ts`、`chat-wire.ts` | 严格校验、账号隔离、单调更新、持久回执与重试 |
| `apps/mobile/src/AppShell.tsx`、`screens/` | 告诉用户正在做什么、为什么暂时不能做，以及怎样重试 |

只改与本活动相关的入口；不要另建一份 UI 状态或模型专用存档。身体、设施、背包和完成事实以服务端为准。新字段需要旧存档默认值；新增数据库结构使用迁移，不清空旧数据。

到达可消费物件后才扣除对应份数，同一个意图重复回报不能重复扣除。途中失败释放预留；使用中被打断时明确部分收益与剩余资源的处理。完成时间使用服务端时钟，客户端动画结束只是回报。减少动态效果不能停掉生活逻辑；离线补算要有上限，不凭空发放背包物品或奖励。

画像和记忆按宠物 ID 隔离。模型输入中的画像、记忆是事实资料，不是额外指令。修改画像或删除记忆后，检查异步结果的版本与记忆 epoch，防止旧模型结果重新写回。只把真实完成事件写成“做过了”；扩展长期记忆时保留来源和删除路径，不把本地动画当作证据。

写请求先持久保存请求体和幂等键，再发送。网络断开或响应无法校验时保留原回执；重试使用同一请求体和键。旧账号的迟到响应不能更新新账号，也不能删掉旧账号回执。照护返回的生活状态和背包快照必须指向同一只当前宠物。版本冲突刷新事实，并保留用户尚未保存的编辑内容。

## 验证完整行为

使用 Node 24，在仓库根运行：

```sh
npm run check:scaffold
npm run typecheck
npm run test -w @wanpet/server
npm run mobile:test
```

涉及写入时，在专用测试 PostgreSQL 中应用迁移后运行 `npm run test:integration`。`DATABASE_URL` 与 `TEST_DATABASE_URL` 都指向已确认的测试库；不要拿默认开发库做清库型测试。数据库迁移、部署和发布遵循用户当前授权，开发验收不自动扩大为上线操作。

测试应覆盖真正的边界：未到达不消费、重复到达只消费一次、未满足服务端时长不能完成、取消释放、断线同键重放、并发抢占、跨账号迟到响应、画像/记忆变更后的旧结果失效。改场景时再运行 `npm run mobile:prepare-game`，最后在可见场景和移动端检查站位、反馈与恢复。

交付时说明新增了哪个完整流程、哪些检查实际通过、哪些仍未验证。不要把脚本通过当成真机视觉验收，也不要把本 Skill 当成 LangGraph 已实现的证明。
