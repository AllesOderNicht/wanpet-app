# 页面、导航与交互

> 当前移动端为 RN 页面 + Godot 互动场景，已迁移的页面与验收证据见 [RN 迁移记录](rn-migration.md)。下文同时包含正式产品规划；聊天、商店、自主出发等规划不表示当前已实现，React/PixiJS/Capacitor 描述为历史记录。

## 信息结构

建议采用「家园 / 旅途 / 收藏」底部三入口，商店和行囊作为独立面板；宠物聊天、资料与设置从家园进入；记忆管理从聊天与隐私设置均可到达。避免逐像素复刻参考游戏的布局。建议竖屏，按安全区与小屏可读性设计。

主路径：启动 → 登录/恢复 → 家园 → 行囊 → 保存准备 → 等待宠物自主出发 → 旅途中 → 归来卡片 → 领取确认 → 明信片详情 → 收藏册。

## 屏幕拆解

| 屏幕 | 核心内容 | 操作与反馈 | 必须覆盖的状态 |
|---|---|---|---|
| 启动/恢复 | 品牌、简短加载、登录入口 | 重试、会话恢复 | 无网络/过期会话/维护 |
| 首次领养 | 原创物种卡、昵称、性格预览 | 选择→确认 | 未解锁、昵称不合法、提交超时 |
| 家园 | 庭院/室内、宠物、资源、当前状态 | 切换场景、看资料、打开行囊 | 在家/旅行/归来待领/缓存只读 |
| 行囊 | 物品栏、推荐用途、已选道具位 | 添加/移除、保存准备 | 空行囊、库存变化、并发冲突 |
| 商店 | 名称、价格、拥有数、用途 | 确认购买；结果显示数量变化 | 余额不足、重复点、价格版本变化 |
| 旅途 | 宠物状态、目的地线索、预计归来 | 查看已有旅记；不提供付费加速占位 | 旅行中、到期、断网、AI 文案待生成 |
| 归来 | 原创明信片、纪念品、奖励明细 | 一次领取、展开详情 | 未到期、已领、领取超时、重试 |
| 收藏册 | 明信片网格、发现度、详情 | 按区域过滤、查看日期 | 空册、未发现剪影、重复收藏 |
| 宠物聊天 | 当前宠物人格、历史消息、真实旅行经历引用、AI 身份提示 | 发消息、停止等待、重试失败消息、进入记忆管理 | 空对话、发送中、离线草稿、服务不可用、内容不可生成、超时结果未知；按消息 ID 去重重试 |
| 记忆管理 | 已存记忆、来源/日期、待确认记忆建议、保留说明 | 逐条查看/确认/拒绝/删除，清除全部需明确确认 | 无记忆、待确认、删除中/失败、已删除；说明历史聊天单独保留或删除规则 |
| 宠物资料 | 物种、昵称、性格、成长记录 | 编辑允许字段 | 保存失败、AI 功能未开放 |
| 设置与隐私 | 声音、动效、通知、数据说明 | 权限按需请求、账号操作 | 拒绝权限、重新认证、删除流程 |

聊天支线：家园 → 宠物聊天 → 记忆管理 → 返回聊天。分享支线：明信片详情 → 分享预览 → 用户确认分享；当前只设计流程，不连接外部分享或发送。

## 交互规范

- 网络请求中禁用同一按钮、明确进行中状态；超时显示可安全重试，不把未知结果当失败。
- 领取反馈必须基于服务器响应。动画可以重播，但不能再次结算。
- 客户端预览道具组合与布局，保存准备不等于立即出发；显示「行囊已备好」并等待宠物自主出发。扣除只能在服务器确认出发事务后发生。调试 start 按钮不作为正式 UI 决定。
- 返回/关闭行囊保留未提交选择；换账号或权威库存变化时重新验证。
- 空态、错误态、加载态和离线只读态都作为正式设计交付，不能只做 happy path。
- AI 文案明确宠物虚拟身份，长文可折叠；旅行叙事生成中使用模板，不显示无限等待。聊天失败保留输入并提供重试，不能把模板当成宠物已理解用户消息。
- 私人聊天与主人记忆默认不进入明信片；分享预览清楚展示实际内容，不自动附带对话或敏感记忆。删除记忆后立即从未来生成上下文排除；历史对话、派生记忆与分享副本的处理边界须明确告知。
- 正文建议 16pt 起、点击区域至少 44×44pt；支持文字放大、对比度、VoiceOver 标注、减少动态效果。颜色不单独承载奖励/错误语义。
- 不依赖声音判断状态，不用强制签到损失、内疚文案或频繁推送制造陪伴压力。

## 待制作的设计交付

1. 低保真：上述 12 屏及所有阻塞错误态。
2. 视觉样板：家园、行囊、归来、收藏四屏，同一 token 与组件系统。
3. 动效原型：宠物待机、出发/归来、卡片打开；可关闭与低性能降级。
4. 真机走查：小屏、刘海安全区、字体放大、前后台切换、断网与连续点击。
