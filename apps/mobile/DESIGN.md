# Design System: 丸宠 · 清晨小家原生界面

## Overview

**状态：2026-10-30，用户已确认首页精简、玻璃底栏、右侧三个图标及全屏导航方案；本轮原生与真机验收记录以 docs/home-navigation-20261030.md 为准。本文其余美术与业务边界沿用原实施约束。**

**Creative North Star: "一个可以直接陪猫的清晨小家"**

延续已批准的日系手绘、暖米色、清晨阳光与微风。小屋与庭院充实而有序，原猫是前景主角，家具承担入口，布包和纸册在家园上展开。完整更换空间构图、导航和面板，保留原猫与真实业务含义。2026-10-30 导航更新：场景上保留悬浮玻璃底栏及右侧工具按钮，功能页采用全屏导航。

设计对照为 [交互稿 DESIGN.md](../../design/2026-10-22-morning-ui/DESIGN.md) 与其实际浏览器截图；原生事实来自 [AppShell](src/AppShell.tsx)、[界面原语](src/screens/shared.tsx)、[功能面板](src/screens/Pages.tsx)、[Session](src/session/Session.ts) 和 [Godot 场景入口](../godot/scripts/rn_scene.gd)。仓库根 `DESIGN.md` 保留旧 Web 实现历史，不作为本次原生界面的覆盖来源。

**Key Characteristics:**

- RN 承载真实文本、账号、玻璃导航与全屏功能页；Godot 承载场景、导航和猫动画。
- 一套（390×844）逻辑构图统一背景、猫与入口位置；所有缩放保持横纵同比。
- 纸白、墨棕和鼠尾草控件对应手绘空间，霞鹜文楷负责标题与主要操作。
- 余额、库存、旅行、奖励和收藏服从服务端，UI 不用演示数据补齐真实状态。

## Colors

前置颜色提取自原生样式。纸白是阅读面，墨棕是主文字，辅助棕是说明，鼠尾草是主操作、选中与设置开关。浅选中面同时配合勾号、描边及可访问选中状态。禁用面仍保留可读文字。木色、叶色、天空和阳光属于插画，不增加为业务操作色。

## Typography

**标题与主操作：霞鹜文楷 Regular，原生字体名 `LXGWWenKai-Regular`。** 字体位于 [assets/fonts/morning](../../assets/fonts/morning/source.json)，来源为 LXGW 的 LxgwWenKai 项目；本地附 [SIL OFL 1.1 许可证](../../assets/fonts/morning/OFL.txt)，记录包含上游地址与 SHA-256。Android assets 与 iOS Fonts 中的副本已核对与该记录一致，iOS 已在 `UIAppFonts` 与 Resources 中登记；这些源码和文件检查不等于真机字体渲染验收。

正文、数字和输入使用平台默认字体。当前逻辑字号/行高：家园标题（29/42）、面板标题（25/35）、主操作（17/24）、物品名（16/26）、正文（13/23）、输入（16）。说明多为（11–12），名称和日期在窄屏允许换行。以下尺寸均为 RN/Godot 逻辑单位，非屏幕物理像素。字体随原生文本系统渲染，不把中文或数量做成图片字。

## Layout

场景基准（390×844），两张背景原图均为（853×1844）。Godot 场景和 RN 家具热点共用居中的 cover 变换：`factor = max(width/390, height/844)`，整体居中裁切；背景本身也以统一缩放覆盖逻辑场景。不能分别缩放 x/y，也不能为了适配不同屏幕单独压扁猫。

首页移除宠物信息卡、陪伴和活动文案、共同记忆及绘图入口，保留场景与猫的直接互动。右侧按安全区顶部加 12 排列三枚 48×48 玻璃圆按钮：设置、聊天、状态，按钮间距 10、右边距 16，仅显示图标并提供读屏名称。

底栏宽度为屏宽的 72%，限制在 280–360；窄于此范围时至少保留左右 16 的间距。最小高度 56，大字体时扩高，圆角为高度的一半。底边距为底部安全区与 12 的较大值加 8。底栏依次是“门外、相册、行囊”，均有图标和名称；庭院时首项改为“小屋”。首项直接切换场景，另外两项切换独立全屏页并显示选中态；相册详情继续属于相册。相册和行囊左上返回进入前的场景。

聊天、状态、设置及其子页采用原生 Stack 全屏导航，隐藏底栏；左上返回及系统返回按页面层级生效。状态承接日常、照顾、画像、旅行与领取；聊天内保留记忆管理和绘图。待领取只在场景“状态”图标上显示圆点。正常首页不显示说明块，异常或待确认操作保留可恢复提示。

全屏纸色页面避让上下安全区，正文占剩余空间独立滚动，页脚操作保持可见；iOS 键盘出现时调整可用高度。相册、行囊及相册详情预留悬浮底栏高度。Native Stack 提供 iOS 边缘返回和 Android 返回；减少动态时关闭页面转场。Godot 宿主位于导航之外，切页不重建，功能页面覆盖期间阻止场景触摸及读屏访问。

## Elevation & Depth

深度以手绘场景的透视、遮挡和阳光为主。iOS 26 起，底栏及右侧按钮使用 UIKit `UIGlassEffect` Clear；旧 iOS 使用系统薄模糊材质，Android 使用暖色半透明底。开启减少透明度或增强对比度时，iOS 切换实色材质。玻璃控件采用（5）垂直偏移、（12）阴影半径和（0.15）透明度；全屏功能页不使用纸卡阴影或场景遮罩。明信片使用浅纸色、轻微旋转与较小投影。窗口、家具和植物已经画在背景中，不重复叠加一套家具节点。

## Shapes

纸面四角按左上、右上、右下、左下为（19、13、14、12），主操作为（17、15、18、16），物品格为（11、8、10、9），输入框圆角（8）。不对称幅度很小，保持整洁。设置按钮为（48×48）圆形；常用主/文字操作和输入最小高度（48），家具热点至少（48×48）。猫和道具按自身透明轮廓显示。

## Components

**场景与原猫。** 房间、庭院、布包为已批准原型美术的逐字节副本，来源见 [原生美术清单](../../assets/godot/morning/provenance.json)。家具入口由 RN 接管，房间数据不再附带不可见食盆或门口路径目标；Godot 只在前景地毯/空地的保守足点区域导航。初始足点为（202.8，649.88），即构图的（52%，77%）。详细证据见 [原生比例审计](../../design/2026-10-22-morning-ui/review/native-proportion-audit.md)。

原猫不裁图、重绘、镜像、拉伸或按每帧透明包围盒重新拟合。原生 pack 使用源锚点，`pack.scale × clip.scale` 作为固定姿态族缩放；不再次乘历史资源打包参数。休息使用完整（121 帧、24fps、约 5.04 秒）源片段，替代浏览器稿的 18 帧局部预览。

| 姿态族 | 源像素到逻辑场景的固定倍率 | 比例输出参考 |
| --- | ---: | --- |
| 完整休息 | 0.1973001038 | 可见宽度中位数约 190 |
| 睡眠/进食/抚摸 | 0.5919003115 | 可见宽度中位数约 190–191 |
| 左右行走 | 0.43 | 可见宽度中位数约 205.54 |
| 正背面行走 | 0.5833333333 | 可见高度中位数约 139–141 |

这些测量来自源帧 alpha 与固定倍率，不是每帧缩放算法。正背面自然较窄，不能强制等宽。原有起身/趴下图像端点比例不兼容，资源仍保留，但当前 pack 绕过可见过渡帧，在休息/行走/生活动作边界使用（160ms）透明度交接；不插值大小。最终连续动作、脚底接触与设备性能仍须看实际运行结果。

**行囊、旅途与收藏。** 布包展示选中道具，下面两列库存显示服务端数量；每类带一份。收起保留当前账号会话内草稿，账户切换或已确认出发后清空。忙碌、离线、有待确认操作、已有旅途或库存冲突时不允许新出发。旅行/待领状态与猫是否在家取自快照；倒计时只辅助阅读，到零仍显示确认中，不能自行改成可领取。领取返回的奖励进入归来面板；相册按首次收藏时间倒序，大图在前、其他小景在后，未知物品有文字/通用图形回退。

**实际服务边界。** 原生已通过 Session 调用登录/注册、改密/退出、初始化、快照、出发与领取接口，不沿用浏览器稿的内存造数或 60 秒定时发奖。写操作先保存按账号隔离的待确认记录，使用原幂等键核对；确认结果前阻止新的写操作，读取成功不会自行消除未知写结果。正式经济与存档由后端契约决定。源码已接入接口不等于本轮已完成部署或服务端验收。

**账号与异常。** 保留设置→账号管理→改密/退出和可取消的退出说明。用户名与密码有真实输入标签和提交状态；当前 UI 要求密码至少 15 字符，服务端仍负责最终校验。改密成功或会话失效后回到登录，退出清空界面草稿；访问令牌只保存在会话内存，关闭应用需重新登录。设置偏好与待确认记录通过平台存储保存；不得将账号口令写入日志、设计文档或本地偏好。离线、加载、损坏记录、库存变更和存档冲突使用清楚文本及恢复入口。

**减少动态与生命周期。** RN 合并应用设置与系统减少动态偏好，并监听系统变化；启用时 Modal 不播放淡入淡出，偏好传入 Godot 以停帧/直接移动。应用后台暂停引擎，回到前台恢复并读取快照；Godot 的隐藏房间停止处理、各房间导航图独立。当前面板覆盖方式不等于暂停整个场景，不沿用浏览器稿的“每次开面板都冻结猫”假设。设置保存失败会明确提示，不能显示为已保存。

## Do's and Don'ts

- **Do** 以已批准的交互稿为视觉对照，以当前业务快照和错误为状态依据；最终一比一效果交由原生验收确认。
- **Do** 保留固定猫比例、源锚点、完整休息片段、场景 cover 与家具入口对齐，优先修正布局，不改造原猫。
- **Do** 保留真实文字、至少 48 单位的主要操作热区、原生输入、关闭、系统返回和减少动态能力。
- **Don't** 把浏览器 36＋6 项检查、资源审计、源码接入或字体副本核对写成原生验收通过。
- **Don't** 恢复首页信息卡和陪伴文案、用客户端倒计时发奖，或用截图代替真实交互。
- **Don't** 将本文覆盖到根 Web 历史规范；本次实现与验收状态尚未完成。
