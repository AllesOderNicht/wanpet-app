# 第一轮实现：让宠物的日子连起来

2026-10-29。本轮落实“按照方案优化，暂不使用视频生成，可以生图”。这是原方案的第一轮可运行改造；并不表示整份长期方案已经做完。

## 现在接通了什么

- **宠物画像**：能编辑名字、描述、说话感觉和三个性格倾向。画像和原宠物绑定，聊天与自主活动共用，旧宠物、旧性格和经历保留。
- **生活闭环**：吃饭、喝水、上厕所、看书和已有活动共用一套流程。先走过去，服务端确认开始使用，再结算结果。不会把走路时间当成吃饭时间。
- **真实照顾**：添基础口粮、用背包食物、添水、清猫砂盆。能看到实际份数、清洁度、需要和心情。重复请求不会重复扣背包；断线后有待确认入口。
- **记忆接入**：自主活动可读取这只宠物的相关长期记忆；删除记忆或更新画像后，旧模型选择不能晚到后重新生效。生活经历仍保留为单独的最近记录，完整的统一记忆系统尚未完成。
- **首页入口**：聊天、照顾、画图、画像、共同记忆、相册和旅行都有明确入口。去掉依赖旧背景家具位置的悬空热点。
- **制作流程**：仓库新增两个可复用 Skill，说明怎样接通新活动、怎样制作并验收场景素材。它们是开发流程说明，没有冒充已运行的 LangGraph 服务。

## 画面怎么改了

先把现有 2D 场景的空间约定修好，作为业务协议落地和画面校准的过渡版本。原方案提出的 3D 小场景尚未完成，也没有用这次 2D 改造宣告 3D 路线失败。

新底图把主要装饰放到后方，地面连续留空。猫窝、食盆、水碗、书和猫砂柜是独立物件。宠物整体缩小；站位、嘴与碗口的接触点、猫窝前沿和柜体碰撞使用同一套逻辑坐标。移动软垫会同时移动前沿，不再只移动其中一层。

这次新增五张图：房间、猫砂柜、书、饮水碗、吃饭/阅读姿势图集。均使用内置生图，PNG 保留真实透明通道，来源、参考图和哈希已登记。没有生成新视频。原行走、睡眠、休息动画继续使用；新吃饭/阅读是两帧姿势，尚不具备完整的骨骼动作和连续转身。

视觉验收更正：用户指出进食时碗穿入脸部、睡眠身体没有真正进入窝内。此前把逻辑接触点与前沿排序检查当作画面验收，结论不成立；这两项仍未通过，需要重新校准姿势、真实接触位置及窝内遮挡。截图来自当前移动端所用的同一套 Godot 4.5.1 场景，不包含 RN 浮层，也不等于手机真机验收。截图目录见 [场景预览](preview/README.md)。

## 怎样接入现有开发环境

新增的 `202610290001_pet_profile` 是增量迁移，不删除旧表、旧宠物或历史。Prisma 客户端已重新生成，测试迁移只应用于新建专用测试库。当前开发库、远端环境没有迁移或部署；没有推送代码。

在确认要运行新版的本地数据库后，按现有开发说明执行 `npm run db:deploy`，最小权限账号同时更新 `ops/grant-runtime.sql`，再启动新版后端和移动端。不要把测试库命令拿去清理开发数据。发布前仍需要完整原生编译、真实模型和设备验收。

## 后续仍要做的部分

1. 按原方案完成一个固定镜头 3D 样例，用同一套活动协议比较遮挡、接触、动作和手机性能。现在的 2D 层次修复保留作可运行过渡。
2. 建立真正的资产生产流程：生成 → 检查比例/透明/站位 → 预览 → 安装为可互动资产 → 可回滚。当前“画点新想法”产出的是插画，不能自动变成家具或新宠物。
3. 把生活事件、长期事实、关系与习惯统一到有来源、可纠正、可删除的记忆体系。当前相关长期记忆采用关键词筛选，不应宣传为已经完成完整记忆大脑。
4. 增加多宠物领养与切换、更多身体类型、通用物件能力、执行权/物件版本，以及玩家端可恢复的生成工作流。当前玩家仍沿用一只宠物的存档结构，画像已是一宠一份。

这些边界决定下一步的验收内容，不影响本轮已经接通的生活、照顾、画像和场景流程。
