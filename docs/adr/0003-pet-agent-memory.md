# 宠物对话与自主行动分工

聊天使用 TokenHub Haiku 和 Codex SDK，Jev 继续负责真实猫的家园决策。聊天工具只能提出一次家园动作邀请，服务器校验并记录接受、拒绝、延后及实际执行进度。模型的自然语言不直接改变库存、旅行或奖励。

聊天原文、工具执行结果和用户可管理的记忆条目由业务 PostgreSQL 保存。mem0 OSS 使用单独的 pgvector 数据库与火山方舟豆包向量 API 提供记忆提炼、合并和检索，记忆及查询文本会发送至火山方舟。每轮 Codex 使用独立临时环境，应用显式提供近期对话及记忆。这样会放弃 SDK 自动跨轮恢复，但能在用户纠正或删除记忆后彻底重建生成上下文。

记忆删除立即在业务层生效，并更新宠物上下文版本。旧向量命名空间异步清理；旧生成与提炼任务不能写回新版本。当前以单实例 API 为运行边界，扩展副本前必须增加记忆维护的持久租约。

## 工具与记忆执行边界

Codex 0.164.0 在关闭常见开发功能后仍附带通用 MCP 资源工具，因此增加仅供该轮使用的本地 Responses 代理：请求只保留两项宠物工具，返回流中任何非宠物调用在到达 CLI 执行器前中止。真实 TokenHub 密钥只存在于代理进程；CLI 只持有本轮随机凭据。白名单兼容性用真实 CLI 生成的请求验证，不能仅凭配置名称断言工具已关闭。

记忆检索的等待预算为 10 秒；异步提炼、重建允许 120 秒。mem0 的一次提炼可能包含两轮模型调用，不能沿用短查询的超时。重建按业务条目 ID 保留进度，超时重启继续同一上下文版本；完成后才发布新索引。客户端删除立即生效不依赖重建成功。

近期对话包含结构化邀请结果和当前进度，避免后续回复把新一次延后误解为上一次接受无效。延后不创建动作承诺；意图被替换会结束旧邀请等待。只有场景的有效完成回传才可写入共同经历。
