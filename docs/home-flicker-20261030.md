# 家园闪屏修复

## 问题链路

原 GameSurface 将渲染启停、状态同步、房间切换及事件轮询放在同一个 effect。生活快照或回调变化都会重复调用 resume 和 surface。新增回归在旧代码失败，确认普通生活刷新也触发渲染恢复和房间重选。

AppShell 同时维护 RN 静态场景底图和 Godot 动态画面，两者在不同线程更新；房间变化时静态底图先更新，导致原生表面短暂露底时可见不同场景。宿主父 View 又随页面切换改变 pointerEvents 和无障碍属性，默认可折叠；原生桥接在父视图移除时会解绑 Godot 渲染层。这是必须消除的原生层级不稳定因素，不能用 React 组件实例未变证明安全。

AppState 把 inactive 当成 background，导致上划手势仍在进行时就主动暂停渲染。

## 实现

- 游戏显示期间只由 Godot 绘制场景；RN 静态图仅用于未进入游戏的阶段。
- 两级原生宿主 View 设置 collapsable=false，避免页面交互属性变化改变原生挂载层级。
- 引擎启停仅依赖 ready/active，状态同步与事件轮询各自拥有生命周期。
- 房间命令按已确认目标去重；发起切换立即使缓存失效，防止快速 A→B→A 忽略最后一次 A。
- Godot 对重复选中当前房间幂等返回。
- inactive 保留当前渲染状态，background 才暂停，active 恢复；房间选择不随生命周期重置。

## 验证

移动端类型检查、7 套共 58 项组件测试通过，包含普通快照刷新、快速往返和 inactive/background/active 回归。Godot 桥接、生活回归与双端资源打包通过。

这些检查验证代码机制，不能代替真机逐帧验收。更新后的 iPhone 已由用户完成重复切页、上划和恢复验证，结果见下方真机验收。

签名 iPhone Release 构建通过；修复版已覆盖安装并启动，Bundle ID 保持 com.wanpet.playtest。用户已在小屋和庭院分别复测功能页往返、多任务手势返回、回到桌面后重新打开 App，明确确认“这些操作都不再闪屏”。本次报告的闪屏问题通过用户真机验收；该结论不扩展为所有设备或长期性能均已验收。
